# Project Name & Brand Guidelines

> **Candy is the current working name of this open-source project and repository. It is not necessarily the final name of any future published application, service, company, or commercial product. A future release may use a different product name and brand identity.**

This document governs use of the project's current identifiers while the repository is known as Candy. It should not be read as a promise that a future public product will be released under the Candy name.

The source-code license and project branding are separate matters. The open-source license applies to code and other materials explicitly released under that license. It does not automatically grant permission to present an independent project, distribution, service, account, logo, domain, or visual identity as official or endorsed by this project.

## Working Name vs. Future Product Name

For now:

- **Candy** refers to the working project and repository name.
- documentation may use Candy as shorthand for the architecture, concepts, prototype, and research direction being developed here.
- feature names that include Candy are provisional unless explicitly stated otherwise.
- the final public application may be renamed before release.
- a future product name may have its own branding and usage policy.

Renaming the eventual application does not require the historical project documentation or repository lineage to pretend that the Candy working name never existed.

## Allowed Uses

You may use the Candy working name for factual references, such as:

- "based on the Candy project"
- "forked from the Candy repository"
- "compatible with the Candy project"
- "an unofficial fork of Candy"

You may also link to the repository, discuss the project, review it, contribute to it, or build independent work based on the source code under the project license.

## Forks and Modified Versions

Forks and modified versions should use their own primary names.

A fork may explain that it is based on the Candy project, but it should not present itself as the official Candy project unless it is maintained or explicitly approved by the project owner.

Good examples:

- "MyProject, based on the Candy project"
- "An unofficial Candy fork"
- "Compatible with the Candy project"

Avoid examples:

- "Candy Pro" without permission
- "Official Candy" without permission
- using the Candy working name, logo, or visual identity in a way that makes an independent project look official when it is not

## Uses That Need Permission

Please ask for permission before using the Candy working name, logo, domain, or official project visual identity for:

- a public app, website, package, or hosted service whose branding may appear official
- a commercial product or paid service presented under the Candy working name
- a social media account or community that may look official
- merchandise, paid assets, paid plugins, or marketplace listings using official project branding
- a modified distribution that uses Candy as its primary product name

If the eventual application is released under a different name, that product may use separate brand guidelines.

## No-Confusion Principle

The main rule is simple: users should be able to tell what is maintained by this project and what is independent.

Current Candy project identifiers should not be used in a way that confuses users about who maintains, approves, operates, or is responsible for a project, service, account, or distribution.

## Future Rename

If the public application receives a final name later, the repository can update:

- product-facing names
- logos and visual identity
- domains
- marketplace or service names
- public-facing brand guidance

The Candy working name may remain in development history, research notes, commit history, or repository lineage where preserving provenance is useful.

## Contact

Brand permission, final product naming, and official contact details will be added as the project grows.
